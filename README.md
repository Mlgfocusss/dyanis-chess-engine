# Dyanis — chess engine

Собственный шахматный движок на Go. Сначала разрабатывается и
тестируется полностью локально (CLI, perft-тесты), позже
компилируется в WebAssembly и подключается к React-фронтенду
(без бэкенд-сервера — статичный деплой на GitHub Pages / Vercel).

## Статус

- [x] Шаг 1 — представление доски и генерация ходов
      (включая рокировку, взятие на проходе, превращение пешки)
- [x] Шаг 2 — perft-тесты (стартовая позиция + Kiwipete)
- [x] Шаг 3 — minimax + alpha-beta (негамакс), фиксированная глубина
- [x] Шаг 4 — оценочная функция: материал + piece-square tables
      (таблицы Michniewski; отдельные midgame/endgame таблицы и
      tapering по фазе игры — только для короля)
- [x] Шаг 4.5 — книга дебютов (Polyglot .bin): Zobrist-хеширование,
      чтение/декодирование `.bin`, взвешенный выбор хода, подключена
      к поиску как приоритетная проверка перед запуском negamax
- [х] Шаг 5 — UCI-протокол (uci/isready/position/go/quit, книга подключена, SAN в -play)
- [х] Шаг 6 — итеративное углубление и таймер
- [ ] Шаг 7 — компиляция в WASM
- [ ] Шаг 8 — React-доска и деплой

## Первым делом

Замени `github.com/yourname/dyanis-chess-engine` в `go.mod` и во всех
импортах на свой реальный путь (например `github.com/<твой-ник>/dyanis-chess-engine`),
если планируешь публиковать репозиторий под своим именем.

## Как запустить

```bash
# Все тесты (включая perft на стартовой позиции и Kiwipete)
go test ./...

# То же самое, но без медленного perft depth=5
go test ./... -short

# Напечатать стартовую позицию
go run ./cmd/cli

# Напечатать произвольную позицию по FEN
go run ./cmd/cli -fen "r3k2r/p1ppqpb1/bn2pnp1/3PN3/1p2P3/2N2Q1p/PPPBBPPP/R3K2R w KQkq - 0 1"

# Perft с разбивкой по ходам (полезно для отладки генератора ходов —
# сверяй total с эталонными числами, см. internal/perft/perft_test.go)
go run ./cmd/cli -perft 3

# Интерактивная игра в терминале против движка.
# Ходы вводятся в обычной шахматной нотации: e4, Nf3, O-O, exd5, e8=Q —
# координатная запись (e2e4) тоже по-прежнему работает.
#
# По умолчанию -play подключает книгу дебютов assets/gm2001.bin, если
# файл на месте (см. "Опционально" ниже, откуда его скачать) — пока
# текущая позиция есть в книге, движок играет из неё мгновенно, без
# поиска. Если файла нет — не ошибка, просто предупреждение в stderr
# и игра идёт без книги.
go run ./cmd/cli -play -depth 4

# Явно указать другую книгу:
go run ./cmd/cli -play -depth 4 -book assets/komodo.bin

# Явно отключить книгу, даже если assets/gm2001.bin существует:
go run ./cmd/cli -play -depth 4 -book ""
```

По завершении партии (мат/пат) в `-play` печатается полный лог в
стандартной нотации вида `1. e4 c5 2. Nf3 Nc6 3. ...`.

### Опционально: книга дебютов

`-play` без `assets/gm2001.bin` работает и так — книга просто
пропускается с предупреждением. Чтобы включить её, скачай любой
Polyglot-совместимый `.bin` (например `gm2001.bin`, `komodo.bin` —
доступны в открытых репозиториях с шахматными книгами) и положи в
`assets/`.

## Архитектурные заметки

- **Board.MakeMove копирует доску**, а не делает make/unmake с откатом.
  Это проще и надёжнее на этапе, пока важна корректность (perft), а не
  скорость. Профилировать и, если нужно, переходить на make/unmake —
  отдельная задача на будущее, когда движок уже играет.
- **internal/** — все пакеты недоступны для импорта извне модуля.
  Осознанно: движок ещё не публичный API.
- Массив `[64]Piece` — простое представление на старте. Если позже
  понадобятся битборды для скорости, `movegen`/`search` не должны
  трогаться — они работают через методы `Board`, а не напрямую с полем
  `Squares`.
- **Книга дебютов проверяется до поиска, не внутри eval.** Вес хода в
  книге ничего не говорит о статичной оценке произвольной позиции
  глубоко в дереве поиска — это решение уровня "какой ход играть
  прямо сейчас", поэтому оно живёт как проверка в самом начале
  `search.BestMoveWithBook`, а не как слагаемое в `eval.Evaluate`.
- **`Board.Hash()` сейчас считается заново с нуля** при каждом вызове
  (обход всех 64 клеток). Это нормально для редких обращений к книге,
  но станет узким местом, когда хеш понадобится на каждой ноде поиска
  для транспозиционной таблицы (шаг 6) — тогда его стоит сделать
  инкрементальным полем `Board`, обновляемым в `MakeMove`.
